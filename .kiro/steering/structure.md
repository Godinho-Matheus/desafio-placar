# Estrutura do Projeto

A estrutura final do projeto deve seguir a arquitetura definida no design da Spec ativa do Kiro.

## Princípios

- Manter responsabilidades claramente separadas.
- Evitar classes com múltiplas responsabilidades.
- Evitar camadas e abstrações sem necessidade real.
- Utilizar nomes de classes, métodos e pacotes que expressem claramente sua função.
- Manter uma estrutura adequada ao tamanho e à complexidade deste desafio técnico.
- Não aplicar padrões arquiteturais apenas por preferência ou sofisticação.

## Áreas esperadas

O projeto provavelmente terá responsabilidades relacionadas a:

- domínio e regras de negócio
- persistência
- API REST
- mensageria
- Redis
- interface web com Apache Wicket
- configuração
- testes

A organização final dos pacotes deve ser definida no `design.md` da Spec antes da implementação.

Após a aprovação do design, este documento pode ser atualizado para refletir a estrutura real adotada.
